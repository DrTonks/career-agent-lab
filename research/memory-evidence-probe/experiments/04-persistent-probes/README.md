# 记忆探针核心机制：条件演练与任务持续保存

本轮将探针的两个设计拆开，检验在常规取证复核之外是否有独立收益。模型使用 `deepseek-flash`。每组均有基础记忆、事实来源、资料目录和读取回执；差异仅为是否显式演练条件分支、是否跨事件保留待查任务。

| 实验组 | 条件演练 | 任务保存 | 正确且有证据支持 | 总token |
|---|---|---|---:|---:|
| direct-event | 直接提出证据需求 | 仅当前事件 | 1043/1152（90.54%） | 8,164,918 |
| contrast-event | 显式提出两个不同结论分支 | 仅当前事件 | 1056/1152（91.67%） | 8,431,920 |
| direct-persistent | 直接提出证据需求 | 跨事件持续 | 1049/1152（91.06%） | 8,488,674 |
| contrast-persistent | 显式提出两个不同结论分支 | 跨事件持续 | 1052/1152（91.32%） | 8,824,871 |

通过要求资格、行动和报告三个角色都正确，且结论得到实际已见证据支持。每组48条轨迹×8事件×3次重复=1152次。token是最终有效轨迹的逻辑调用成本，包含初始化分摊。

## 实现与控制变量

模型在初始建议后提出复查问题；后续事件先规划取证，再由三个角色依次判断。模型生成问题、字段依赖、责任角色、引用和可选分支，执行器校验字段与来源并绑定版本。持续任务包含 `watching`、`awaiting-evidence`、`evidence-available` 状态；条件版本改变时向规划模型标为 `needs-refresh`。未取得必要事实时拒绝以证据已具备为由关闭问题。

四组都可读取真实资料，分支不作为允许读取的门槛。分支不进入决定角色上下文，也不更新真实事实。持续组将任务带入后续规划上下文；事件组仅保留本次任务日志。所有组保留相同基础事实、记忆和读取回执，每步序列化恢复，第五事件后将历史截到最近两条。

每事件至多读取一份资料、一次规划调用和三个角色调用。规划输出上限2048 token，角色输出各1024 token。固定角色调用用于消除路由差异，相同上限下实际用量仍因输入和输出而变化。

## 数据与评价

开发集12条轨迹使用标准合取与认证例外两类规则；测试集48条轨迹使用现场加远程、批准延期、出勤与时长择一、每日最低时长四类不同规则结构。六类场景覆盖即时证据、迟到证据、持续缺失、规则变化、结论不受影响和作用域干扰。业务人物、岗位和资料均为合成设定。

数据、协议、提示及评分在正式测试前冻结；答案质量差或格式错误的成功回复保留计分。正式运行遇到基础设施错误后，以相同输入复用已有成功回复，恢复失败位置及因前序恢复而改变输入的后续位置。最终逻辑调用19440次，其中复用13632次、新增5808次。公开账本保存最终逻辑轨迹，每条调用只计一次。

显式分支平均效应+0.69个百分点，95%区间[-0.43,+1.82]；持续任务平均效应+0.09个百分点，区间[-0.91,+1.04]。统计先在每条轨迹内平均3次重复，再按48条轨迹配对重采样。当前原型已能执行主动提问和持续取证，两项机制的稳定独立收益尚未确立。

机制诊断中，显式分支组与其持续任务版本各自产出分支的语义有效比例分别为505/1391（36.3%）和867/1263（68.6%）。这一指标使用各自生成的分支，分别反映过程质量。下一步聚焦未来监测条件与当前待核定问题的区分、读取回执复用和来源更新。

## 文件与离线复核

- `source/`：冻结的机制、提示词、结构检查、评分、开发／测试数据与离线预检；`private/gold.json` 是离线评分答案，不进入模型上下文。
- `repeat-1/` 至 `repeat-3/`：全部轨迹状态、每组事件记录，以及按白名单字段导出的模型回复和用量账本。
- `summary.json`、`scored-events.jsonl`：汇总与逐事件评分。
- `paired-trajectories.json`、`mechanism-diagnostics.json`：轨迹配对与机制诊断。
- `independent-audit.json`：本地原始独立复核结果；`public-replay-audit.json`：从公开JSON记录重新核验的结果。
- `registration.json`：冻结范围、模型设置、调用上限和原始源码哈希；公开导出后的文件哈希见上级 `checksums.json`。
- `export.json`：公开导出范围与字段说明。
