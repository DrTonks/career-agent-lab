# 产品与研究资料

核对日期：2026年11月7日（产品文档复核）。

| 资料 | 采用的事实与设计参照 |
|---|---|
| [Hindsight Staleness-Aware Memory](https://hindsight.vectorize.io/blog/2026/06/17/freshness-aware-memory) | 标记整合记忆相对新事实的滞后，引导回查原始事实。 |
| [Letta Memory](https://docs.letta.com/agent-sdk/memory) | 持久及共享记忆、Git版本管理、后台整理对话并更新记忆。 |
| [Graphiti Overview](https://help.getzep.com/graphiti/getting-started/overview) | 时序知识图谱、事实失效处理、历史查询与来源追溯；Graphiti是Zep的开源框架。 |
| [StateGraph](https://arxiv.org/abs/2611.02912) | 依赖感知的长期记忆修订、反事实依赖验证与选择性传播。 |
| [COUNTERMEM](https://arxiv.org/abs/2609.31874) | 通过可执行世界模型验证替代动作，并保存反事实记忆。 |
| [CRITIC](https://arxiv.org/abs/2305.11738) | 借助外部工具反馈进行检查与纠错。 |

本方案的设计切口是把“何时需要重新考虑建议”纳入长期记忆：由模型提出复查问题，绑定目标建议、证据需求、责任角色与版本，保存为可跨事件续办的任务。现有产品比较描述公开能力与本项目侧重点；机制的收益通过四组消融对照单独检验。

本轮补充的差异化细节：把当前声明与历史叙述分离，并对公开时间规则检查候选反例是否真的改变判定；分别记录当前提交和预测解决。它是复核任务层的实现选择，可叠加在上述记忆能力之上。
