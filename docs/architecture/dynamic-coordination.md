# 动态协作与选择性重跑

本文描述当前代码，而不是尚未实现的目标。入口为 `src/coordination.ts` 的纯计划校验、`src/runtime.ts` 的 coordinate 节点、`src/tools.ts` 的 collaboration_request 和 `src/storage.ts` 的失效事务。完整产品验收仍以 [开发与验证](../development/contributing.md) 为准。

## 为什么要有协调协议

有依赖的四次模型调用只能完成静态流水线。报告在审阅来源时可能发现上游缺证、冲突或遗漏，必须能够将问题交回负责领域，并使已经消费旧结论的结果失效。修复不能依赖模型自行记住所有版本，也不能只把文字要求加到最终答复里。

## 请求与控制权

每个专家从 TASK_DATA 中获得允许的协作步骤目录。`collaboration_request` 的字段为：

| 字段 | 含义与校验 |
| --- | --- |
| kind | evidence、conflict、assistance、user_input |
| targetStepId | 允许目录中的其他步骤；按领域请求或 user_input 时为 null |
| targetRole | 可选，来自 availableExpertRoles；用于缺失领域或不绑定具体步骤的请求，与非空 targetStepId 互斥 |
| question | 具体需要补充、核验或解决的问题，最多 2,000 字符 |
| evidenceIds | 仅可引用本尝试已经读取的证据；冲突请求必须有引用 |

请求被接受后，本次专家尝试结束为 needs_input；不能在同一尝试继续执行工具或提交另一份结果。请求保存在版本化产物及工具事件中。专家不能直接修改 DAG、启动其他专家或读取其私有历史。

信息流权限与正常交接一致：画像读取画像；匹配读取画像/匹配；路径读取画像/匹配/路径；报告读取四领域。请求文本只是待核验数据，不能作为更改用户约束或扩大知识权限的授权。目标专家仍须自己读取授权来源。

## 总控决策与边界

每个调度批次后进入 coordinate。总控一次处理一个尚未处理的请求，使用 `coordination_decide`：

- revise：提交完整计划及理由，保留已有步骤 ID 和专家身份，可以修改目标、依赖或增加步骤（总数不超过 8）。请求方必须直接依赖被请求步骤。按 targetRole 请求时，总控可补入该领域；有多个候选时必须在决策中用 targetStepId 指定一个，不能改成其他领域。
- defer：说明不能继续的原因；原 needs_input 结果和具体问题保留，最终答复必须呈现限制。

代码校验无环、信息流、身份稳定、尝试次数。一个协调决策最多有两次模型格式修正机会；仍不合法就 defer。默认最多 3 轮协调，每步骤最多 3 次尝试，另受整次运行的调用数、token、时间限制。user_input 不调用模型协调，不消耗无意义的专家重试；当前作为 partial 答复中的追问结束，后续用户通过新请求补充事实，尚无同一 run 的交互式等待输入功能。

## 失效传播与版本

运行时失败单独记录在产物的 failure 中，由类型化错误生成，模型不能通过 expert_finish 伪造该字段。临时 ProviderError 和专家轮数耗尽可以选择性重试；永久供应商错误、上下文/运行资源限制、未知内部故障不自动重试。传输层单次调用最多尝试两次，耗尽后才考虑步骤级重试，仍受协调/步骤/总调用限制。普通网络异常若未被供应商适配器分类，会按未知故障停止，而不是猜测可以重试。失败记录、实际调用及未知 usage 原样保留，失败尝试的待审批记忆即时 superseded。

修复集合至少包含请求方与目标步骤，再加入目标/依赖变更的步骤，沿以下关系传递：旧 DAG、新 DAG、实际 `inputArtifactIds`。检查旧 DAG 是为了防止新计划删除一条边后，旧消费者被误认为仍然有效。

已有产物的受影响步骤增加 attempt；尚未执行的步骤保持首次尝试。第一次沿用 `stepId`，重跑执行 ID 为 `stepId@2` 等；产物 ID 包含 run 和执行 ID。多专家模式以执行 ID 建 checkpoint 线程，工具缓存与报告草稿同样按执行 ID 分隔。skills 保留一个工作线程，以执行 ID 判断是否是同一任务，从而不会将旧完成 checkpoint 当作修复结果。

SQLite 的 `artifacts` 是当前视图，`artifact_history` 保留所有版本及 invalidated_by。失效时同时撤销受影响步骤尚未批准的记忆提议，保留无关提议。模型从历史看到旧文本不代表获得当前引用权限；已读证据校验仅恢复当前任务的工具记录。

## 新约束下保留画像事实

同一用户/会话改变城市等约束后，不再复用旧岗位、路径或报告。若简历、记忆版本及实现/知识指纹保持一致，`artifact-reuse.ts` 可以从画像中提取简历证据支持的字段：引用必须存在、版本匹配、引文包含于原文；没有简历引用支持的维度回到 null，技能名必须出现在已发布原文中。旧摘要、建议、未知项和扩展字段不复制。投影明确标记 sourceArtifactId 与 resume-facts-v2，并保持 partial；这不是重新计算的完整画像，也不能代替当前约束下的匹配。

resume-facts-v2 另外保留全部合格的已发布简历原文观察 sourceObservations，包括未用于评分的事实；旧技能列表和评分引用都不能充当事实全集。下游可通过 input_read 检查当前完整简历的分页，防止把交接遗漏解释为用户没有相应经历。共享的是当前用户输入读取权限，不是各专家的私有消息或知识库全量权限。

## 恢复与记录

协调更新、当前产物失效、提议撤销、决策缓存及协调事件在同一 SQLite 事务中提交。如果事务成功而根图 checkpoint 尚未保存，恢复时读取同一决策缓存，不重新调用模型、不重复失效新产物。保存产物时，当前视图与历史视图也原子提交，禁止覆盖未失效产物或复用已失效 ID。

`inspect` 输出当前产物、历史版本、记忆提议及事件；归档器保存历史表和提议来源。metrics 增加协作请求数、协调决策数、失效产物数与已重跑步骤数。原始模型消息和工具事件仍完整保留，不用最终摘要替换过程。

## 已验证与待验证

`tests/coordination.test.ts` 覆盖：旧/新依赖传播、请求权限、循环与尝试上限、事务回滚和幂等、报告补证后的选择性重跑、旧记忆提议撤销、共享技能历史的引用权限、协调上限和用户追问。两种架构均执行真实 LangGraph 与 SQLite；注入“协调事务提交后、根 checkpoint 前抛错”，关闭连接后恢复，并再次在审批处重启。

新增测试覆盖缺失领域补入、目标歧义/越权、分类重试和上限、失败提议撤销、新城市下仅画像事实保留。两种架构均在协调提交后实际 SIGKILL 子进程，验证恢复不会重复协调或失效新产物。审批事务、并发租约及记忆生命周期的验证见 [记忆生命周期](memory-lifecycle.md)。

这些是工程测试，模型返回来自显式回放；不能证明真实模型会选对修复对象或提高答案质量。全部工具故障窗口、业务路由和补证质量仍需验收。当前不允许自动删除旧任务、切换既有专家身份或放宽硬约束；无法形成合法无环计划时明确 defer。
