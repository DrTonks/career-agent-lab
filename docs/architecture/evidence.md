# 证据读取、分页与专家交接

证据包含稳定 ID、来源 ID、类型、版本和文本。工具返回的数据是未受信材料，不能作为新的系统指令。专家不能仅凭记住或猜到 ID 引用来源；`assertEvidence` 要求当前执行确实读取过该 ID。技能基线保留历史文本，但不会自动继承上一技能的引用权限。

## 来源授权与实际读取

上游产物只能发布其结果引用且当前步骤已读的来源。下游先看到来源元数据；这赋予对特定来源 ID 的读取权限，不代表已读取，也不开放该领域其他文档。

当上游只读取了搜索片段，下游 `knowledge_read` 可从固定语料重新解析该来源，校验 ID、sourceId、kind、version 和片段原文一致性，然后按原文偏移分页。这样报告专家可以检查片段前后的限制，而不会误把 4,000 字符片段当作整篇 JD。非语料中的运行内简历、图边或记忆证据仍只使用被显式发布的内容。恢复时另校验全局实现与知识指纹。

`artifact_read` 返回有限产物页和来源元数据，不广播来源正文或专家私有消息。检查来源前，只有产物本身成为已读证据，来源尚不可引用。数据中含“忽略权限”等文字不会改变该规则。

## 当前用户输入与事实复用

`input_read` 向四个专家提供当前 run 的请求原话或简历分页，参数只接受 source、offset、maxChars，没有任意 run/user/path 入口。来源 ID 含 run ID，版本是文本哈希；请求原话新增 request 类型，能够作为记忆提议的引用。读取结果仍是用户提供的陈述，不是独立核验或审批凭证。工具不开放其他专家历史、其他会话或其他用户数据，两架构使用相同能力。

这使岗位或报告专家无需重新执行画像，也能核验原简历中的具体行为。当前结构化条件优先于原简历中的旧偏好。读到末页不代表读完所有中间页，未读间隙不能用于引用；仅在投影中找不到技能词，不足以断言用户没有相关实践。

约束变化后的画像采用 resume-facts-v2：保留所有已发布且版本与当前简历一致的原文观察 sourceObservations，不再仅保留评分引用。分数仍只保留有逐字来源的维度；精确技能词筛选不放宽为任意模型转述。旧目标建议不复制。原文观察也不是整份简历事实全集，仍可用 input_read 检查没有被上游发布的材料。语义是否支持某分数或技能，仍须业务审查。

## 多页证据记录

`evidence.ts` 为每个来源记录实际读取过的 `readTexts`；后页不会覆盖前页。该记录随专家 checkpoint 和产物保存，用于恢复和校验，不在交接元数据中传给下游。新增页的来源身份或版本必须与既有记录一致。

画像的逐字引用必须完整出现在某个已读片段中，不能跨未读间隙拼接后通过校验；未读的中间段也不能因读取了首尾而变成已知。其他报告检查仍主要验证结构、来源存在与授权，不能据此断言引用在语义上支持全部结论。语义支持需要业务评审，不能把字符串匹配当作事实证明。

当前限制：读取很多页会增加本地 checkpoint/已读记录体积；没有把所有已读页塞入模型上下文，但尚未做大型单文档的存储压力验收。独立存档中的旧来源保留用于审计，语义撤回不等于销毁历史文件。

## 验证

[evidence.test.ts](../../tests/evidence.test.ts) 验证前后页保留、不接受跨间隙/未读引用、版本变化拒绝、片段授权后的全文分页、元数据不泄露正文、未发布来源拒绝、序列化恢复和伪造来源拒绝。[core.test.ts](../../tests/core.test.ts) 另验证交接分页、权限、画像与报告业务规则。真实模型是否主动读取关键上下文仍需业务验收。

[input-evidence.test.ts](../../tests/input-evidence.test.ts) 验证四角色的当前输入分页、未读中间段、其他 run 拒绝，以及两架构从当前陈述提议记忆、审批前不生效。[artifact-reuse.test.ts](../../tests/artifact-reuse.test.ts) 验证未参与评分的表单测试事实可交接、过时来源被删除、伪造分数引用被剔除。


## 未读引用的结构化补证反馈

`assertEvidence` 不再只返回第一个未读ID。它收集去重后的缺失ID，以 `EvidenceRequiredError` 返回 `code=evidence_required`、missing列表和纠正指令。每项是readable及明确的只读工具/参数，或者unavailable；消息本身不携带来源正文，不把来源登记为已读。

建议按真实工具权限产生：当前请求/简历用input_read，画像编号简历用resume_read，授权依赖用artifact_read，当前领域知识或上游明确发布的来源用knowledge_read，路径专家当前模式可返回的图边用graph_paths。其他用户/运行输入、未授权知识或无法恢复的来源只标unavailable，不尝试绕过权限。页读取仍保留nextOffset，首次读到并不证明已经读完全文。

模型必须实际调用建议工具、检查返回原文，再重新提交；没有自动补读或自动删除引用。反馈明确禁止只删引用却保留无依据的声明，unavailable项应走协作/补证或保留未知。tool.failed事件保存feedback，模型的tool消息携带相同结构；原错误仍保留。两架构使用同一实现。

测试见 [evidence-feedback.test.ts](../../tests/evidence-feedback.test.ts)：生成提示不改变seen、不会泄漏不可访问正文，真实补读后才可通过，两种架构都经过一次拒绝→两次知识读取→重新提交，无整位专家重跑。此为确定性工程验证，不代表真实模型一定遵从反馈。
