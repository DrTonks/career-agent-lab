# 技术选型与组件职责

当前使用TypeScript、LangGraph和SQLite实现CLI智能体核心，依赖版本由package-lock.json固定。选型围绕显式状态、领域边界与持久恢复，不以框架名称代替业务能力。

| 层 | 当前实现 | 选择理由 |
| --- | --- | --- |
| 运行与类型 | Node.js 24+、TypeScript、Zod | 统一类型和运行时校验；CLI输入、工具参数与产物契约明确 |
| 编排 | LangGraph总控图与专家工具循环 | 显式表达步骤、依赖和审批恢复；专家私有消息与权限由业务运行时管理 |
| 持久化 | SQLite/WAL、自定义checkpointer、事务与租约 | 本地可运行、可检查，支持进程恢复；长期记忆与执行checkpoint分开治理 |
| 模型接入 | OpenAI兼容HTTP流，当前配置支持DeepSeek | 传输、工具参数、usage和失败统一处理，领域逻辑不绑定供应商 |
| 检索 | BM25；可选本地BGE/ONNX向量与RRF | 默认无向量模型也能运行；先授权、再筛选和检索；索引与查询编码必须相容 |
| 观测与测试 | SQLite事件、JSON导出、协议回放与进程故障检查 | 保存错误、重试和未执行状态，核心不依赖外部观测服务 |

独立专家不需要四套数据库或四个进程。当前用共享数据上的角色授权视图分隔知识，用独立步骤历史与产物契约分隔上下文。框架本身不负责画像语义、岗位硬条件、记忆审批或来源有效性，这些由领域工具与运行时实现。

没有同时维护Spring、pi与LangGraph三套实现；当前重点是已有智能体机制。将来只有出现明确需求或兼容性问题才重新选择框架，不能从本仓库的架构对照推导框架性能排名。

参见[运行时](../../src/runtime.ts)、[存储](../../src/storage.ts)、[模型传输](../../src/providers.ts)、[检索](retrieval.md)与[实现边界](../development/implementation-status.md)。HTTP服务与独立展示demo属于适配层，不是核心运行的前置条件。
