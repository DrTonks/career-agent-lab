# 检索计算证据与路线引用

岗位原文和用户简历不能直接证明“当前筛选后有几个候选”。这类结论来自工具执行，必须保留查询范围、约束和实际结果。`calculation`是独立的证据类型，用于这些可追溯计算，不冒充岗位原文或个人能力证据。

## 记录与授权

[calculation.ts](../../src/calculation.ts)定义`tool-calculation-v1`：运行ID、专家尝试、角色、约束版本、数据版本、知识执行指纹、工具、实际参数和结果。完整正文的hash构成版本与ID，源码与运行快照共同解释其计算规则。hash证明绑定关系，不单独授予访问权。

计算原文保存在当前运行的`tool_cache`，键为`calculation-source:<id>`。读取必须同时满足：有真实存储回执，正文和ID/hash一致，运行/约束/知识快照一致，并且属于本专家尝试或由当前授权输入产物显式发布。仅知道ID、自己构造一个合法hash或从其他run拿到引用均不够。

生产工具返回完整计算来源并登记为实际已读。下游先获得发布元数据，再用`knowledge_read`分页读取；发布不是已读。产物只发布其`evidenceIds`实际引用的来源，最终核验只获得实际发布/已读部分。计算记录中的用户查询仍是不可信数据，不能修改工具权限。

## 零岗位与聚合统计

`jobs_search.evidence`记录实际硬约束、筛选前数量、合格/未知数量、类别覆盖与排除计数、返回候选ID和数据范围。空结果也有来源，可支持`rankedJobs=[]`的partial提交，不必发明岗位ID或者读取不存在的候选。

计数范围是所选语料和当次类别过滤，候选列表还有排名/数量限制；不能改写成整个市场没有岗位。聚合计数不会授予被排除岗位的读取权限，也不表示逐一读过原文。零合格候选、硬条件未知候选、没有该类别语料必须区分。

## 记忆数量与授权范围

`memory_recall.evidence`也是计算来源，`dataScope=authorized-memory`。`counts.totalAvailable`是共享与当前角色命名空间内、状态过滤后且查询前的数量；`totalMatches`是查询匹配数量；`returnedCount`只代表当前页。`memoryScope`包含角色命名空间、记忆快照、query、includeInactive、mode、limit、cursor和nextCursor。零命中不能推出授权全集为空，任何一种角色范围也不能冒充整个用户的全部记忆。

计数回执不保存记忆值。`includeInactive=true`可计入失效或撤回条目的版本头，因此不能用它证明活跃记忆数量。当前运行记忆发生变化后，旧回执读取会被执行快照检查拒绝。向下游显式发布回执只授予该计算来源；下游自身的`memory_recall`仍按自己的命名空间检索。

[memory-calculation.ts](../../src/memory-calculation.ts)检查参数、角色、快照格式与数量关系；核验字段补读同时读取范围，拒绝用孤立数值或岗位计数支持记忆数量。词法规则仍不能解决全部自然语言主体与范围歧义。正常、越权、交接、过期快照和同值错误绑定见[memory-calculation.test.ts](../../tests/memory-calculation.test.ts)。

## 路径提交

`graph_paths`返回两层来源：整个有界搜索的计算回执，以及每条路线的`routeId`和`routeEvidence`。路线来源保留实际节点、图边、成本、模式与请求参数。无结果只说明当前快照、查询和深度范围内没有返回路线，不说明现实职业路径不存在。

`expert_finish.artifact.paths`每项可提交`routeId + actions`，并将routeId列入`evidenceIds`。运行时检查授权/已读节点/快照/工具类型，还原nodes并再次核对当前图边，然后保存带节点的产物。后续CLI、指标和报告仍可读取规范化nodes。jobs_search计算来源不能冒充routeId。

仍兼容明确nodes的提交，要求实际读过所有图边；同时提供routeId和nodes时必须一致。不存在的边返回`invalid_graph_edge`，包含准确的source/target和本次已读的有效路线引用，不向模型暗中开放全库。修正后的提交重新走全部校验，不把错误响应当成功。未读取路线节点时返回具体读取位置；没有引用所选routeId也会拒绝。

## 恢复与限制

来源ID由绑定内容生成，同一次工具缓存重放保持相同ID。来源已保存、工具总回执尚未保存的窗口允许确定性重算，已有来源不重复插入。取消后不允许新增计算来源。普通工具回执、来源原文、事件与checkpoint共同随现有归档保存；用户遗忘按照运行缓存生命周期处理，不声称删除既有独立归档。

计算证据不能用于`profile_score`的个人评分，评分仍要求用户来源。图边存在不证明转岗建议适合用户；筛选正确不证明语义排序或行动计划正确。相关单元与集成测试见[calculation.test.ts](../../tests/calculation.test.ts)，其中两架构均验证错误边反馈到模型后按路线引用修正。注入来源保存窗口故障的用例是确定性故障测试，不冒充该新窗口的实际进程终止测试；其他既有SIGKILL检查继续单独记录。

## 核验中的计数字段绑定

[calculation-review.ts](../../src/calculation-review.ts)将直接检索计数与计算回执绑定，防止仅凭专家摘要便判定统计有依据。它不增加新的知识权限，也不是通用自然语言蕴含证明器。

核验输入的`calculationCandidates`标记`beforeFilter=8`等明确字段，以及带语料/候选/筛选语境的“4条、1条合格”等直接表述，保留单元ID、原文区间、数值和指标。候选识别采用保守的词法规则，区分百分比与计数，保留负数、小数和千分位，避免把小数截成整数。它不覆盖所有中文数词、推导比例、比较句、范围或省略句，不能据此宣称全部统计已被自动识别。

`calculationFacts`只从具有有效来源身份的规范JSON计算回执生成。必须实际读取查询/快照身份、存在的约束和数据范围字段，以及具体标量；类别计数还需读完整类别行。代码按原始JSON偏移验证覆盖，不把不同页的间隙当作已读。目录中的字段名不生成事实，篡改正文/版本或只读一个孤立数字也不生成事实。

事实操作明确区分`scalar`（原字段）、`length`（完整已读类别数组的长度）和`all_equal`（完整已读非空类别数组的指定字段逐项相等）。这使“6个类别”不必错误绑定到岗位数量；已识别的“每类别”计数也不能用某一行代替全部行。异值数组、空数组或未读完整数组不能形成全称值证明。以上是代码计算的直接结果，不授权模型自由编写公式或执行表达式。

模型提交`calculationClaims: [{candidateId, factId}]`。对已识别且判为supported的计数，必须逐项绑定；代码检查候选归属、重复、实际可用事实、字段类别、值相等，以及原文明示的类别ID与计算类别范围。`calculationBindings`回执保留JSON指针、原文字段偏移、查询参数、约束、数据范围及候选原文，供后续审计。

缺少绑定会返回`calculation_evidence_required`并进入原有一次协议纠正；模型可在剩余两轮补读范围内取得计算原文，再完整重交。不自动补造绑定，不提高调用限制。未能证实时可明确unsupported，既有草稿修订/保留流程继续适用。

代码能验证直接值与指定字段、显式类别ID，不能完全验证中文类别别名、多个查询之间的叙述口径、因果归因或正确的语义分类；把事实误标为建议、未识别表述等仍需语义评审。相关回归见[calculation-review.test.ts](../../tests/calculation-review.test.ts)。两种架构均验证真正补读后才通过提交，不能用这些确定性回放推断真实模型质量。

针对完整任务中“在硬条件下，语料仅1条候选”被误当语料总数，计数限定现在可跨逗号延续，但在句号/分号结束；最近的明确筛选前/后限定优先，明确语料总量仍是总量，未知与排除数量保留独立字段。单独出现“语料”只说明数据来源，不自动确定为筛选前计数。仍是有限词法规则，不能证明所有条件句、中文别名和省略表达都正确。

分段审核中的calculationFacts同时提供已读回执的查询范围（工具、参数、约束、数据范围、类别），不再只发一个数字与字段路径。v9发送时以scopeId关联calculationScopes表中的scope，同一来源与范围只发送一次；内部事实仍保留完整scope。模型必须比较查询口径；这些元数据不扩大原文读取权限，不证明所有自然语言限定都匹配。成组字段/数值/边界、相同数字不同口径和无损范围关联的反例见[review-scope.test.ts](../../tests/review-scope.test.ts)。

数量候选不会仅因整行含“岗位检索”就把“18个月”截成“18个”岗位数；月份、星期、小时、季度、学期、工作日、自然日的时间单位被排除，同一行真实的候选数量仍须绑定计算回执。“待核实”与“待核验”的前置数量限定均表示uncertain。该词法边界有成组反例，仍不是覆盖所有中文量词的通用语义解析器。

v8审核支持[字段补读](final-review.md)：请求counts或categoryCoverage字段时同时带入该计算的实际查询身份、约束、数据范围及必要类别整行。来源仍是未改写原文区间，calculationFacts沿用实际覆盖校验，不凭目录或一个数字放行。规范JSON偏移实现共用[json-locations.ts](../../src/json-locations.ts)。不同查询的数值不同可能完全合法；代码暴露参数并校验引用身份，仍不代替模型判断任意自然语言口径。

## v10类别合计与全称范围

jobs_search按每条记录的单一categoryId分组，输出categoryPartition（single-category-per-record-v1及recordCount），未映射类别明确为null。原始计算回执保存该声明，字段补读附带实际分组声明。求和还检查类别行互异、总记录数与beforeFilter及逐类总量相等；每个被加字段须为不超过该类总量的非负安全整数。

sum仅用于同一已读回执、明确命名的多个互斥类别、同一个统计字段。scope包含quantifiedCategoryIds及operands的原路径和数值，身份hash绑定操作和实际类别集合。必须完整读到类别数组、查询身份、约束、数据范围及存在的partition。不能混加不同查询，不能把同一类别的city和experience排除数相加（同一记录可能重复违反条件），不能用beforeFilter恰好相同的值冒充排除总数。旧回执没有partition时不补造sum能力。

all_equal表示实际类别集合的字段逐项相等，“各4条”不能用sum=8代替；一个句子中分号分隔的不同类别陈述分别绑定。支持实际类别ID和frontend-mid/senior这类共享前缀缩写，识别到不存在的同族类别时不生成聚合证明。自然语言类别别名、复杂指代和任意算式未实现，模型仍须检查查询口径，代码不宣称完整语义解析。测试见[calculation-aggregates.test.ts](../../tests/calculation-aggregates.test.ts)。
