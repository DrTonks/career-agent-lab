# 用户追问续接

完整更正样例为[correction.json](../../evals/examples/correction.json)：通过reply整体替换简历和约束，纠正实习、改变城市并保留双休硬要求。使用同一用户和当前最新父任务：`npm run cli -- reply --run PARENT_ID --user USER_ID --case evals/examples/correction.json --live`。样例是公开合成用户材料，下游仍应重新核验未知条件和失效结论。

`reply` 把用户对上一轮的回答提交为一个明确关联的新任务；`resume` 只恢复同一任务的中断执行。源码在 [follow-up.ts](../../src/follow-up.ts)、[Runtime.reply](../../src/runtime.ts) 和 [Store.followUp](../../src/storage.ts)。这不是交互式终端聊天 UI，仍使用可脚本化的 JSON 文件。

## 使用

父任务必须属于指定用户，且是该会话最新的 `partial` 或 `succeeded` 任务。`partial` 中即使综合答复被保留，专家的问题和未知项也可作为续接上下文；它们不被当成已核验的个人事实。正在运行、等待审批、失败或取消的任务不能通过 reply 跳过原状态处理。

```json
{
  "operationId": "reply-001",
  "reply": "补充：本人负责Vue表单开发和提交测试。请根据新材料更新画像。",
  "resumeText": "本科应届。本人负责Vue表单开发和提交测试。暂无企业实习。",
  "constraints": { "cities": ["成都"], "experienceYears": 0 }
}
```

```powershell
npm run cli -- reply --run PARENT_RUN_ID --user USER_ID --case reply.json --live
```

`reply` 与 `operationId` 必填。省略 resumeText/constraints 表示继承；传空字符串明确清空简历，constraints 对象为完整替换而非局部合并，`{}` 会清空旧的显式条件并应用默认值。父任务的用户、会话、架构和审批要求保持；不能借回复文件切换身份或把新事实写成已批准记忆。

同一用户的 operationId 只能对应同一父任务与规范化内容。重试返回原子任务，不能创建第二个；完成或等待审批的子任务由 CLI 直接返回，未完成的子任务沿原执行/租约机制继续。内容或父任务不同会拒绝。同一父任务的另一个新回复不能越过已创建的最新子任务，避免旧分支悄悄覆盖当前输入。

## 状态与来源

续接会持久化父任务 ID、操作 ID、父输入哈希、当前输入哈希、原始回复、材料替换标志，以及父专家已发布的未知项和 user_input 协作问题。快照有独立哈希；规划、专家执行及恢复验证其一致性。

新续接使用 `user-reply-v2`：当前 request 只含本轮回复，历史原文通过[原始输入历史](input-history.md)的授权祖先链目录与分页读取，不再递归拼接。专家通过 `input_read` 读本轮输入，通过 `input_history_read` 读旧轮次；只有实际返回的原文页可引用。每条消息仍有原长度上限，但累计历史不受单条40000字符约束。旧 `user-reply-v1` 数据保留原拼接解释方式，不能用新契约重写封存材料。旧助手答复和问题不变成用户证据。

总控看到全部问题目录；各专家只看到本领域的历史问题。它们用于决定是否已补齐、是否还要追问，不是个人事实、知识授权或完整旧专家历史。用户新回复可能更正历史陈述；当前明确更正优先，但实现没有通用的自然语言事实合并器。冲突未解时需澄清，必要时用户可提交完整替换简历，不能宣称任意语义冲突均已自动消除。

## 输入版本、原子性与复用

`conversation_inputs` 保存用户/会话输入版本，`follow_up_commands` 保存幂等映射。创建子任务、提升输入版本、更新约束版本、保存父子关系与事件在同一 SQLite 事务中完成。重复请求在事务内首先查映射。事件观察者仅收到已提交事件；观察者失败不回滚已经提交的子任务，重试仍能找回它。

每次 reply 都增加输入版本，即使简历或结构化条件不变。旧版本执行在当前状态检查处被拒绝，旧版本产物也不会被后续 run 重新拾起。这是保守的跨轮复用边界：新回复可能改变事实，不能因为城市和简历字符串相同就复用旧评分。新任务由总控选择所需专家；它内部仍支持 DAG 选择性重跑与失效传播。当前没有声称跨输入版本可以自动证明并复用未受影响的旧产物。

旧运行和产物留作审计，不改写为新版本结果。用户遗忘操作同时删除续接映射与输入版本；独立归档仍遵循原有备份生命周期。存储迁移为 v4，旧运行未存 inputVersion 时按0解释。归档工具同时导出两个新表，完整数据库备份保留其事务状态。

## 问题如何解决

父问题现在有稳定questionId。相关专家完整读取当前输入后，用clarification_update记录已回答、部分回答或仍未解决，并在正常结束前完成登记。已知部分带原文引用，未解决部分保留为具体字段。状态与能力评分分开，详见[追问解决记录](clarification.md)。

## 验证范围

[follow-up.test.ts](../../tests/follow-up.test.ts)验证两架构实际运行时的追问→回答读取→评分更新，角色问题视图、旧助手文本不进入个人来源、父状态/身份/租约限制、显式清空、快照篡改拒绝、事务回滚与通知、CLI重复命令、版本失效与遗忘。真实子进程在子任务写入后但提交前、提交后两处强制退出，重试均只有一个子任务与一条续接事件。

回放验证协议与状态执行，不代表模型已理解新回复，也不代替独立业务质量评审。完整检查、真实模型多轮结果和剩余问题应以对应批次日志与验收记录为准。
