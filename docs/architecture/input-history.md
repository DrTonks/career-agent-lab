# 原始用户输入历史

状态：已接入总控和四专家，新 `reply` 使用 `user-reply-v2`，当前 request 只保存本轮回复；历史原文不再递归拼接。每条消息原有长度限制仍有效，累计历史可以超过40000字符。旧 v1 数据按原契约重建，不改写原记录。长会话真实模型质量尚未验收。

## 记录与身份

[conversation-inputs.ts](../../src/conversation-inputs.ts)将已有运行行和 `follow_up_commands` 命令回执组成 `user-input-timeline-v1` 视图。首轮取原始 request，后续轮只取 continuation 中单独保存的 reply。绝不按文字分隔符解析拼接后的请求，也不把旧助手答案、问题或压缩摘要当作用户原文。

没有增加重复存储表：原始回复、父输入/当前输入哈希和替换标志已经随创建子运行的事务落库。读取检查数据库行身份、同一用户/会话/架构、祖先链、逐轮输入版本、快照哈希、命令身份和请求重建。整个检查在一个 SQLite 读取快照内完成，允许嵌套在调用者事务中。哈希用于发现不一致，不是抵御能够同时重写数据库与哈希的管理员攻击。

每轮包含原文及哈希、父运行、操作 ID、输入版本、有效简历与结构化条件的哈希、两类替换标志。视图哈希包含整个授权输入链，排除会更新的助手输出和运行状态；恢复同一输入不改变视图。历史陈述不会自动覆盖当前结构化条件，领域工具仍负责执行当前硬约束。

## 目录、搜索和分页

- `conversationInputs`：从指定运行向父运行追溯，只返回当前祖先链；同一会话的其他根运行不会被自动拼入。
- `inputHistoryPage`：目录每页最多20项，支持对授权链原文的字面搜索。目录仅含身份、哈希、长度和替换标志，不授予原文引用权限。
- `inputHistoryRead`：按来源 ID 和字符偏移读取，每页最多8000个 UTF-16 代码单元，返回原文全文哈希及精确区间。非本视图来源、未来轮次、越界读取均拒绝。

来源 ID 形如 `input:<当前运行>:turn:<输入版本>:request`，属于当前运行的授权视图，不是直接开放父运行的来源权限。每次调用重新读取数据库身份，用户遗忘后不能用旧视图恢复已删除原文。独立备份的删除仍遵循[恢复与归档说明](recovery.md)。

记录层上方的 [input-history-tools.ts](../../src/input-history-tools.ts)提供共享访问契约；总控和专家均有 `input_history_list` 与 `input_history_read`，但各角色/各尝试的已读回执分别保存。目录不产生证据；读取工具仅发布实际返回的原文页。恢复缓存时重新核对授权链、页内容、来源哈希和缓存身份。回执记录精确区间，工具返回不重复发送两份原文。

## 总控、专家与压缩

总控先读取需要的历史，再单独提交 `plan_submit`。每个响应最多三个历史读取调用；计划提交不能与读取混批。默认规划最多12个模型轮，完整任务配置为24轮，仍受总调用与运行容量限制。规划也使用软上下文目标压缩，完整调用/返回成对处理；历史目录与读取位置进入结构化工作摘要，但摘要不授予引用权限。

固定任务消息只包含历史快照身份、总轮数和当前输入版本。动态已读页数只进入每次模型调用的 `EXECUTION_STATE`，否则进程重启后会改变原请求身份，导致已完成响应无法恢复。状态中保留最近20个读取区间和总数，完整回执仍在数据库。总控读过的原文不会自动变成专家已读，skills保持其连续工作上下文，但引用权限仍按当前角色执行。

历史原文可用于有引用的行为评分、追问解决和待审批记忆提议；当前请求/简历的完整读取要求不因读过历史而豁免。旧轮次的明确缺失不能单独证明当前仍缺失，因此不能直接支持当前零分。历史正面经历是否已被更正仍需语义核验，代码没有通用事实合并器。下游补读历史也使用 `input_history_read`，其他运行视图的来源不能借交接授权绕过。

最终综合接收已执行计划和专家结果；最终审核的可选原文库包含完整授权用户时间线及其版本顺序，审核仍按分段选源/补读规则操作，不把全部历史固定塞入每次模型请求。独立多轮评审导出按各运行记录的 v1/v2 版本重建用户输入。

## 验证与剩余工作

专家的重复读取控制位于[history-read-loop.ts](../../src/history-read-loop.ts)。只检测当前专家当前尝试连续成功执行的同一批`input_history_read`，以真实缓存结果指纹比对，忽略调用ID、默认参数写法和批内顺序。三批相同后，下一次`EXECUTION_STATE.historyReadLoop`要求改变动作；五批相同后以`expert_no_progress`明确失败，不自动从头重试。新增页、其他业务工具和正常的间歇原文核对不受此规则阻断；既有证据权限、评分和提交校验不变。检测是针对已观察循环的有限保护，不能识别所有交替循环或保证模型能正确推进。

状态从持久模型调用和当前尝试工具缓存重建，不依赖压缩摘要或内存计数器。重建时排除当前及未来模型轮，因此响应已保存但checkpoint尚未推进时不会提前累计一次。失败、未知或未成功读取的结果不构成已成功重复读取。实际进程退出与恢复的机制边界见[故障恢复](recovery.md)。

[conversation-inputs.test.ts](../../tests/conversation-inputs.test.ts)验证10轮持久输入、目录/分页/权限、数据库重开和遗忘。[history-runtime.test.ts](../../tests/history-runtime.test.ts)对两架构建立累计超过10万字符的10轮记录，再执行真实运行时代码的回放：总控六次原文读取、至少三次实际压缩、专家独立重读并形成评分；检查实际发送消息、工作摘要、状态回执和当前条件。该测试不是十轮都由真实模型完成的业务实验。

两架构另在总控响应保存、总控读取完成、专家读取完成三个位置实际 SIGKILL，再通过新进程恢复，检查模型调用作用域无重复、读取回执不重复、其他角色未获授权。另覆盖目录不等于已读、未读页间隙、缓存损坏、外部来源借交接绕过、旧零分拒绝、当前原文澄清与记忆提议、v1→v2连续链。

真实长会话已开展多个开发批次，包含中断和失败，见[最终观察与边界](../evaluation/results.md)。开发批次的执行与AI会话评价已有汇总；运行机制与业务质量分别判断。工程回放与故障测试不代替模型语义质量验收。
