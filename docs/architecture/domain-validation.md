# 领域校验与语义边界

模型负责解释证据；工具负责执行可检查的不变量。格式、引用和计算通过，不等于解释一定正确。本页描述当前代码，专业规则分别在 [画像](../../knowledge/profile.md)、[匹配](../../knowledge/match.md)、[路径](../../knowledge/path.md)、[报告](../../knowledge/report.md)。

## 画像评分 v2

`profile_score` 使用 anchored-levels-v2-uncalibrated。12 维未校准描述性评分不用于心理诊断、就业概率或直接对齐未经共同校准的岗位能力分数。

- 非 null 观察必须引用当前已读的 resume/request/memory 来源及逐字引文；规则、岗位、图边和模型产物不能证明个人能力。
- 正分依据为 behavior 或 credential；0 分必须明确标为 explicit_absence。未提供信息是 null，不能用0替代。
- 同维度、同来源 ID、同引文的重复观察会被拒绝，避免重复计权。不同引文描述同一事件的语义去重仍需评审。
- 0–4 等级映射到0/25/50/75/100，不同有效观察按 confidence 加权；confidence 是模型给出的描述性权重，不是经校准概率。
- 最终画像必须沿用工具计算值；系统写入实际评分版本。缓存恢复只接受当前评分版本，跨实现/知识版本恢复由运行指纹拒绝。

`internship` 在 v2 明确为企业实习经历。无企业实习不等于无实践能力，校园项目仍能支持专业技能和执行等有证据的维度。同名历史岗位字段可能是其他口径，未经校准不直接比较。没有评分所需材料时保留原文事实并追问，不强填12维。

工具不能自动证明引文支持“学习”“领导”等语义判断，也无法凭字符串确认用户自述属实。规则给出逐维证据条件；真实回答仍需业务评审。修改规范必须升级版本并重建知识索引，不把新规则悄悄套用到历史运行。

### 明确缺失的提交检查

[profile-grounding.ts](../../src/profile-grounding.ts)实现`explicit-absence-context-v1`。本次未修改v2的评分锚点或领域知识；增加的是零分依据的执行检查，运行指纹随源码和提示词变化，旧运行不能用新代码恢复。

在已读来源、逐字引用和basis校验之后，零分还需对应维度的明确自述。比如“暂无企业实习经历”可作为实习缺失自述；“未写实习”“没有实习证明”“没有SQL经验”不能证明整体实习或专业技能维度为零。它检查原请求/简历上下文，避免只截出“无企业实习”而丢失同句否定、他人、假设、过去时间或模板前提；确认记忆仅检查当前value，不借用originalEvidence中的旧否定。部分JSON页不能证明完整记忆上下文。

支持的是有限、明确的表达形式及中英文部分句式，不是通用蕴含证明。可能冲突、未覆盖或过于复杂的表述要求澄清，不能将拒绝提交理解为用户陈述虚假。个人自述也不是外部核实。正分的维度映射、含蓄否定、跨段时间与事实真实性仍需语义评审，不能因该模块存在宣称全面解决评分依据。

失败返回`profile_basis_unsupported`、维度、原引文和原因；整次评分不更新、不写成功工具缓存。模型可核对原文后提交有依据的观察，或保留null并提问；不可只换basis标签。接受的零分检查作为`absenceChecks`和`groundingVersion`随评分结果持久化，原始请求、失败和修正均保留。

`needs_input`同样不能提交未经工具计算的非null画像。空产物或全null画像允许直接用于追问；带分数的画像必须与已完成的profile_score结果一致，并满足引用要求，不再通过状态字段跳过校验。

## 岗位硬条件的四种状态

`jobConstraintCheck` 与 `jobs_check` 返回每项 requested、observed、status。字段包括城市、月薪下限、学历、经验和双休。

| 状态 | 含义 | 示例 |
| --- | --- | --- |
| not_requested | 本次未设此项筛选 | 未设置月薪下限，不是已满足某个薪资目标 |
| satisfied | 已设条件，来源字段足够且通过 | 0年经验满足明确的应届岗位门槛 |
| violated | 来源明确与条件不符 | 指定成都，岗位在西安 |
| unknown | 已设条件但来源无法核实 | 要求双休，岗位工作制字段为空 |

`eligible` 只表示所有已指定硬条件通过；未设置项不参与筛选，不代表全面合适、仍在招或能录用。0年经验、0薪资下限、false工作制均是显式值，不能按空值处理。学历输入“不限”表示不启用学历筛选，不能当作用户学历等级0。岗位城市为空且指定了城市时是 unknown，非确定异地。

搜索在排名前执行硬条件；未知候选单列。categoryCoverage 统计所选类别在 top-k 前的语料与排除原因，原因可以重叠，不可将条件筛选零结果理解为没有该类别语料。

`dataScope` 区分数据来源：synthetic 的 recruitmentStatus 为 not_applicable，合成岗位没有真实招聘生命周期，不能表述为“是否在招未知”或建议投递；private 的状态为 not_verified，需要另行核实。两者都不能凭数据更新时间声称实时在招。

技能交集仍是已提供技能词与岗位词的精确交集，不是能力深度证明。missingSkills 不能自动转译为用户不会该技能；应核对当前原文和所需实践深度。

## 路径与报告

路径检查真实类别、图边、环和长度；图边 score 是排序权重，非晋升成功率。当前经验不足不能被解释为未来永久不可达；快照无出边不代表真实职业没有出路。

报告检查结构、授权来源及草稿版本，未读来源会被拒绝。修正错误的工具往返必须保留，不能从记录里删除。当前虽有 [最终核验与一次修订](final-review.md)，仍没有能可靠证明每句自然语言断言成立的语义验证器；最终综合仍可能写错专家数量、扩大图谱结论或误述未知项。这些是业务验收问题，不能由工具零失败或测试全绿消除。
